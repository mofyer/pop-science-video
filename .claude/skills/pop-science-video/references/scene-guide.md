# 怎样写一镜

这份约定讲一镜的画面代码怎么写、角色怎么驱动、怎么自己预览。短片直接写进 `visuals.mjs`；长片每镜一个文件放在 `src/scenes/`，由 `tools/build.py` 拼起来。两种写法里，场景函数本身是一样的。

把镜头分给几个子代理并行写时，把这份文件连同下面“先读”里的材料一起交给它们。

## 先读

| 文件 | 读什么 |
|---|---|
| 这一期的节拍表 | 你那几镜的旁白、场景、每个节拍发生什么、怎么交给下一镜、上屏标签 |
| `src/script.py`（长片） | 每镜的旁白和节拍键。节拍键就是代码里用的 `b('键')` |
| `engine/STAGE_CONTRACT.md` | 引擎对画面代码的约定和禁用写法 |
| `references/motion-grammar.md` | 画面该怎么动 |
| `kit.mjs` | 开头的目录，以及你要用到的函数；角色、转场、道具都在里面 |
| `examples/opus_animation/src/scenes/` | 写完的一镜是什么样 |

## 长片里每镜交什么

每镜两个文件，放在期目录的 `src/scenes/`：

**`sNN.js`**：定义 `function sceneNN(ctx, f, s, L, vis)`。这一镜专用的辅助函数和顶层常量，名字一律以 `sNN_` 开头（所有文件最后拼成一个作用域，重名会出错）。不要改 `kit.mjs`；缺道具就在自己的文件里写。

**`sNN.json`**：

```json
{
  "labels": {"s07_four": "4 条硬规则"},
  "sfx": {"start": "whoosh", "card": "drop", "act": "pop"},
  "cut": "band"
}
```

- `labels`：这一镜上屏的全部文字，键以 `sNN_` 开头。
- `sfx`：节拍键（或 `start`，即本镜第一帧）到音效名。可用 `pop`、`tick`、`ding`、`rise`、`drop`、`whoosh`、`sparkle`。`start` 一般配 `whoosh`；镜内再挑 2–4 个重点动作，不要每个节拍都配。
- `cut`：怎么交给下一镜。`"band"` 是色带扫过；`[x, y]` 是从屏幕上这一点圆形展开，填本镜结束时那个物体在**屏幕上**的位置（过了镜头变换之后）。
- `pause_after`：可选，旁白说完后停多少秒，缺省 0.3。最后一个节拍离镜尾太近、动作演不完时再加长。

## 场景函数的参数

```js
function scene07(ctx, f, s, L, vis) {
  const t = f.t, b = key => s.beats[key] - s.start, D = s.end - s.start, talking = L < s.voice - s.start;
```

- `f.t` 是全片时间，用来做常驻微动（眨眼、晃动、飘动）。
- `L` 是镜内时间。`b('键')` 是某个节拍在镜内的秒数。**所有动作的时间都从 `b()` 取，不手写秒数**；配音后每个节拍落在那个词说出口的时刻。
- `D` 是本镜总长，`talking` 表示旁白还在说。
- `vis` 是标签在转场期间的透明度，每个标签的 `alpha` 都要乘上它。
- 进度写法：`seg(L, b('键'), 时长)` 得到 0..1，再套 `ease.out`、`ease.inOut` 等。

## 硬性约束

画面必须是时间的纯函数：同一个时刻永远画出同一幅画，不保存状态。引擎会拒绝下面这些写法，注释里也不能出现这些词：

- `Math.random`、`Date`、`performance.now`、`fetch`、`import`、`require`、`eval`、`Function(`、`process.`、`globalThis`、外部网址。
- `fillText`、`strokeText`。文字一律用 `f.label(键, {...})`。
- `textContent`、`innerHTML` 这类运行时写字的写法。

需要随机感时用 `hash(序号)`。

角色只是示意，不画任何公司或产品的标识。

## 画面布局

- 画布 1920×1080。地面在 y 850，角色的脚落在 y 856 左右。
- **角色的脚、标签和重要物体都在 y 885 以上**：y 900 以下是字幕区，y 1040 以下是来源行和说明。
- 左上角 x 64–480、y 40–95 是栏目名，标签不要放进去。
- 标签不能出画，也不能互相重叠（引擎的 HyperFrames 检查会因此失败）。同一个位置换标签时，旧的先淡出。
- 标签不要压在角色的脸上。
- 东西不要从画外滑进来或滑出去：高对比的物体被画框边切到，检查会按布局问题拦下。进场用原地弹出或淡入，退场在画内淡出。
- 两三个字的短标签用色牌，不用描边字：描边字的标签框四角可能被判成“文字被遮挡”。
- 背景用 `studio(ctx, t)`（画在镜头变换之前），地面用 `floor(ctx)`（画在镜头变换之内）。需要别的底色时给 `studio` 传两个浅色。
- 每镜一条缓慢推近的镜头：`makeCam(960, 545, 1 + .04 * seg(L, 0, D))`。强调某个物体时可以推到 1.2 左右再拉回，同时把镜头中心往下挪，别把角色的脚推出画面。标签位置用 `cam.p(x, y)` 从世界坐标换成屏幕坐标。

## 角色

**机器人**（主持人）：

```js
const pose = botMix(BOTS.explain, BOTS.cheer, seg(L, b('键'), .3));
const anchors = drawBot(ctx, { ...pose, ...botAlive(t, talking), x: 330, y: 856, s: .9 });
```

- 现成姿态在 `BOTS` 里：`idle`、`wave`、`explain`、`think`、`surprise`、`cheer`、`worry`、`type`、`pat`、`lens`、`stop`、`shrug`。姿态之间用 `botMix(a, b, k)` 过渡。
- `botAlive` 给出眨眼、天线晃动、呼吸和说话的嘴，每次都加，而且**要展开在姿态之后**：`botMix` 返回的是完整姿态（眨眼、呼吸等项都是 0），写在它前面会被盖掉，机器人就不眨眼、嘴也不动。
- `drawBot` 返回 `head`、`top`、`chest`、`handL`、`handR` 的世界坐标，拿东西（放大镜、纸）时把道具画在手的位置。
- `dir: -1` 左右翻转。手臂角度是绝对角度：0 指向右，正值向下。
- 腿很短，**移动用跳**（`hop` 加 `squash`），不要让它走路。
- 手在身前做事时设 `frontL` 或 `frontR`，手臂才画在机身前面。
- 胸前小屏用 `chest` 切换：`dot`、`braces`、`check`、`wave`、`play`、`lines`。

**小人**：`drawPerson(ctx, { x, y: 856, top: '#5b6ee1', hair: '#33262b', ... })`，同一个人全片同一身打扮。表情用 `mood`（`smile`、`worry`、`o`、`happy`）；`adult: false` 是孩子；`style` 是发型（`short`、`bob`、`kid`）。走路只能用 `walk` 参数（会自动转成侧面）；背景按每秒 `SPEED` 像素后退时，相位取 `(t * SPEED / strideOf(adult)) % 1`，脚才踩得住地。能不走就不走。

角色要演：视线跟着正在讲的东西走，说到关键处有动作。不要让角色从头站到尾。

## 动起来

1. **每个节拍都有一件看得见的事在那一刻发生。** 节拍表写了发生什么，照着做；觉得有更好的演法可以改，但每个节拍键都要用上。
2. **完全静止不能超过 2 秒，两次明显变化之间不能超过 4 秒**（引擎会按帧差拦截）。节拍之间用持续的运动填上：传送带在走、声波在跳、指针在动、角色在呼吸和眨眼。只有待机动作的段落不要超过 2 秒。
3. **讲过程，不放结论卡。** 不做标题加要点清单，不做整屏大字。
4. 承载含义的东西（时间轴、滑杆、对勾、清单、曲线、拼图）用平滑缓动，不回弹。角色、徽章、道具、标签可以用 `popIn`、`ease.back`。
5. 第一帧就是一幅完整的画面，主体和角色从一开始就在。
6. 圈出问题用橙色（`ORANGE`、`ORANGE_D`），不用纯红。

## 标签

- 每个不超过 8 个汉字；英文名照原样。只贴在物体旁边，不复述旁白。
- **标签里的数字必须都在制作单的台账里**，否则引擎会拒绝。
- 两种写法，对比度都够：
  - 白字压色牌：`{ size: 52, color: '#ffffff', plate: INDIGO }`，色牌可用 `INDIGO`、`ORANGE_D`、`TEAL`、`INK`。
  - 彩色字加白描边：`{ size: 52, color: INDIGO, halo: '#ffffff' }`，颜色可用 `INDIGO`、`ORANGE_D`、`TEAL`。四个字以上才用。
  - 不要用 `ORANGE`（浅橙）做字色或色牌底色，对比度不够。
- 字号 44–68。出现用 `popIn(L, b('键') + 偏移)` 配 `scale`，`alpha` 乘 `vis`。

## 自己预览

在仓库根目录执行。并行写镜时 `<dir>` 用各自的临时目录，不要共用：

```sh
python3 tools/build.py episodes/<名称> --only S07,S08 --out <dir>   # 只含这几镜的样张
./make-episode preview <dir>
python3 tools/build.py episodes/<名称> --beats S07                  # 预览里每个节拍落在第几秒
tools/snap.sh <dir> "10.5,13.2,18.9"                               # 另外取几帧
python3 tools/beats.py episodes/<名称> S07                          # 配音之后：每个节拍的真实时刻
```

- 预览没有配音：每镜固定 10 秒，节拍按短语在旁白里的位置排。`--only` 里第 N 个镜头占 `(N-1)*10` 到 `N*10` 秒。
- `preview` 每镜取三帧，拼成 `<dir>/evidence/preview-contact.png`，单帧在 `<dir>/evidence/preview/`。**必须打开图实际看**，不能只看命令成功。
- 三帧看不全一镜。每个节拍之后约 0.6 秒的画面都用 `snap.sh` 取出来看一遍，确认那件事真的发生了、没有画坏。
- `preview` 报 `draw failed at …` 就是那一刻的代码抛错了，按提示的时间和镜头去修。
- 看图时逐项检查：角色有没有缺部件或只剩影子；标签有没有压住角色、互相重叠、出画；东西有没有挤在一角或伸进字幕区；这一刻看上去是不是“有事正在发生”。
- 预览把每镜压成 10 秒，真实配音后节拍间隔会拉长。配音出来后用 `tools/beats.py` 看真实时刻，重点查相隔超过 2 秒的两个节拍之间有没有东西在动。
