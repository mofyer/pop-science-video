# 科普动画短片

这个技能产出的是**动画**，不是配了旁白的幻灯片。判断标准只有一条：把成片静音、遮住字幕，观众还能不能看出这一段在讲什么、有没有事情正在发生。做不到，就是在讲 PPT，要重做。

出片用仓库里的引擎（`engine/`）：整幅画面是一块 Canvas，由期目录的 `visuals.mjs` 按时间逐帧画出，全流程不需要任何图像或视频生成密钥。引擎不调用大模型；脚本、事实核实和画面代码由执行这个技能的模型完成。引擎约定见 `engine/STAGE_CONTRACT.md`，开工前先读。

参考样片在 `examples/opus_animation/`（《不会画画也能做动画》，23 镜，约 6 分钟），它的制作单、节拍表和画面代码就是本技能的范本。

## 四条硬规则

1. **不做文字卡片。** 画面上的文字只有两种：贴在物体旁边的短标签（不超过 8 个字），和每个节拍一个关键词。旁白由字幕承担，画面不复述。标题加要点清单、左文右图、整屏大字，一律不做。
2. **每一镜是一个场景。** 有地方、有物体、有一件事随旁白发生：纸带卷成代码牌，滑块推着小球走，包裹在传送带上一道道变样。讲机制就让机制在画面里真的发生一遍，不用结论卡代替过程。
3. **一直在动，而且动在字上。** 每镜一条缓慢的镜头推拉；角色眨眼、呼吸、说话时嘴在动；关键词说到哪个字，对应的动作就发生在哪一刻。镜与镜之间用转场带过去，不硬切。
4. **角色要演，不是站着。** 它会跳进画面、转身去指、惊讶、担心、欢呼，视线跟着正在讲的东西走。

做法和参数见 [references/motion-grammar.md](references/motion-grammar.md)。一镜具体怎么写、角色怎么驱动、怎么自己预览，见 [references/scene-guide.md](references/scene-guide.md)。

## 第一步：脚本与节拍表（给用户确认）

用户给主题或原始脚本后，写出下面三样，等用户确认再动手出片。用户提了意见就改，改完再给他看；没有确认之前不写画面代码、不配音。

**事实台账。** 每一条事实说法写明来源和原文位置，来源要实际打开读过（官方文档、指南、论文、项目自己的代码和说明）。画面上要出现的每一个数字都列进台账。读不到原文的说法不进旁白。旁白不能比来源说得更满：来源说“通常”，旁白不写“总是”；一次实测得到的现象，不写成通用结论。

**旁白。** 每镜一段。口语、短句，每句只讲一件事。第一句直接抛出观众关心的问题，不要“大家好”“今天我们来聊”。字幕在逗号、句号处断开，每一条单独读也要成立。不恐吓，不保证效果，不替专业人士下结论。短片 4–7 镜、230–300 字，约一分钟；用户要长片时按每分钟 240 字左右估。

**节拍表。** 每一镜写清三件事，这是区分动画和 PPT 的地方：

| 项 | 写什么 |
|---|---|
| 场景 | 在哪里，画面里有哪些物体和角色 |
| 节拍 | 3–8 个。每个节拍是旁白里的一个短语，加上它说出口那一刻画面里发生的一件事 |
| 进出 | 从上一镜怎么接进来，怎么交给下一镜 |

节拍要写动作，不写版式。“说到‘跳着取帧’，取景框在时间轴上不按顺序跳，每跳一下取出一帧”是节拍；“出现逐帧渲染的说明卡”不是。一镜里如果有连续 2 秒以上找不出节拍，就补一个动作，或者把这一镜拆短。节拍短语必须在本镜旁白里恰好出现一次。

讲做法、讲工具的片子，动笔前把整条流程和其中每个有名字的工具、机制列成清单，逐项讲到，不用“某个工具”“一台引擎”这类泛称带过。

参考样片的节拍表在 `examples/opus_animation/SCRIPT.md`。

## 第二步：出片

在 `episodes/<名称>/` 建期目录，写四个文件，其余由引擎生成。

| 文件 | 内容 |
|---|---|
| `production-sheet.md` | 事实台账、每镜 `### SXX 旁白` |
| `episode.spec.json` | 标题、栏目名 `series`、音色 `voice`、右下角说明 `footer`、来源 `sources`、每镜的 `reveals`（节拍短语）与 `sfx`、配乐 `music`、动态阈值 `motion`、可选的配色 `accent` |
| `kit.mjs` | 从本技能的 `references/kit.mjs` 原样复制：小机器人与通用小人、镜头与转场、场景元素、道具 |
| `visuals.mjs` | `labels`、每镜一个场景函数、总调度 `draw` |

`kit.mjs` 开头有一份目录，列出全部可用的函数。某一期专用的道具写在该期的画面代码里，不要改期目录里的 `kit.mjs`。

`episode.spec.json` 里把阈值写上，让引擎替你把关：

```json
"motion": {"max_frozen": 2.0, "max_beat_gap": 4.0}
```

### 短片直接写，长片分镜写

七镜以内的短片，直接写一个 `visuals.mjs`，照 `engine/STAGE_CONTRACT.md` 和 [references/scene-guide.md](references/scene-guide.md)。

镜头多的长片，把源文件放进期目录的 `src/`，每镜一个文件，用 `tools/build.py` 拼成 `visuals.mjs` 和 `episode.spec.json`：

```text
episodes/<名称>/src/
├── script.py        旁白与节拍短语的唯一来源，自带 check()
├── episode.json     标题、栏目名、音色、配乐、来源等设置
└── scenes/sNN.js    每镜一个场景函数；sNN.json 是它的标签、音效和转场
```

这样每一镜可以单独拼成样张预览，也可以把镜头分给几个子代理并行写：先把角色、转场、道具和写镜约定定死，每个子代理只写自己那几镜、在自己的临时目录里预览，互不改对方的文件。样片就是这么做的，具体约定在 scene-guide 里。

### 命令

在仓库根目录执行：

```sh
./make-episode doctor                          # 环境自检
python3 tools/build.py episodes/<名称>          # 长片：从 src/ 拼出 visuals.mjs 和规格
./make-episode preview episodes/<名称>          # 静音预览，每镜三帧
./make-episode run episodes/<名称>              # 全流程出片并验收
```

配音阶段会调用 Azure 语音合成，密钥由引擎从 `~/.config/pop-science-video/azure-speech.env` 读取，不要打印它，也不要把它写进任何文件。配音有缓存，旁白没变的镜头不会重复请求。

### 三道自检，缺一不可

1. **预览拼图。** 跑完 `preview` 后打开 `evidence/preview-contact.png` 实际看图：有没有角色只剩影子（说明那一帧画到一半出错了）、标签压住角色、上一镜的文字残留、构图挤在一角。改到没有问题再跑全流程。看不了图的工具要停下来请人看。
2. **引擎验收。** `run` 会依次核对十一项：音视频流格式、时长、完整解码、响度、字幕与旁白逐字一致、上屏数字都能在制作单里找到、禁用说法、首帧非空、逐镜非空、动态阈值（规格里写了 `motion` 才拦截，所以一定要写）、期目录里没有密钥（读不到密钥配置也记为未通过）。任何一项不过都会停下并说明原因，按原因改，不要绕过。
3. **逐段看成片。** 验收通过不等于好看。把成片按 0.7 秒一帧抽出来拼图看一遍：

   ```sh
   ffmpeg -v error -y -i <成片.mp4> -vf "fps=1/0.7,scale=640:360,tile=5x4" <临时目录>/qa-%02d.png
   ```

   逐镜对照节拍表：说到的事有没有在画面里发生，有没有一段画面偏空，动作有没有和字幕对上。有方向的动作（走路、起跳）另外密集抽帧看。

引擎的 HyperFrames 检查默认全片只取 9 个时刻。片子长的时候再加密查一遍，标签重叠、出画这类问题才不会漏：

```sh
node_modules/.bin/hyperframes check episodes/<名称> --json --at "0.25,0.75,1.25,…"
```

条件允许时，事实台账和成片各请一个没参与制作的子代理独立复核：一个对照来源核旁白有没有说过头，一个对照节拍表看抽帧。

### 交付

向用户报告：成片与字幕路径；`evidence/verification.md` 里的验收表和“动态”两项数字；抽帧拼图；还没验证的事。配乐和音效的听感模型无法判断，要明确请用户试听。配音里英文词、缩写和品牌名的读音也要请用户听。

## 容易踩的坑

- **常驻微动要展开在姿态之后。** `botMix` 返回的是完整姿态，眨眼、呼吸这些项都是 0；把 `botAlive` 写在它前面会被盖掉，机器人就不眨眼、嘴也不动。写成 `{ ...pose, ...botAlive(t, talking), … }`。
- **文字不能画进 Canvas。** 引擎会拒绝 `fillText`。画进去的字逃过了数字核对和重叠检查。
- **不要用 CSS 动画做常驻微动。** 实测在渲染出的成片里它不动。所有运动都在 `draw` 里由时间算出。
- **东西不要从画外滑进来或滑出去。** 高对比的物体被画框边切到，HyperFrames 检查会按布局问题拦下。进场用原地弹出或淡入，退场在画内淡出；镜头推近时也别把角色的脚推到画面下沿。
- **两三个字的短标签用色牌，不用描边字。** 描边字标签的四角可能被判成“文字被遮挡”。
- **`popIn()` 在进度为 0 时返回的是一个极小的正数，不是 0。** 用 `if (k > 0)` 会提前画出零尺寸的东西，改用 `> .01` 或直接按时间判断。
- **背景滚动时，站着不动的角色会像在滑行。** 要么所有人都在走，要么背景不动、角色在原地做事。
- **走路用 `walk`，不要自己摆腿。** 小人默认是正面画法，正面摆腿看不出往哪走，甚至像在倒退。给了 `walk`，小人会整个转成朝行进方向的四分之三侧面。机器人腿很短，移动用跳。
- **画到一半出错不会自己暴露。** 合成阶段会把整支片子排练一遍并报出出错的时间和镜头；看到 `draw failed at …` 就去修那一镜，不要试图绕过。
- **弹性回弹只给角色、道具和标签。** 时间轴、滑杆、仪表读数、曲线这些承载含义的东西用平滑缓动，不回弹。
- **动态验收只认够大的变化。** 浅色光晕、淡底色、背景飘的圆都不算“明显变化”。一段旁白期间如果只有角色在待机，就补一个看得见的动作。
- **中文音色读英文和缩写可能不准。** 旁白里的写法决定读法，例如大小写混写的缩写可能被读成一个音节。读音靠改旁白里的写法来调，画面标签上的写法可以不同。
